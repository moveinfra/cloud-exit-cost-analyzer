# cloud-exit-cost-analyzer

**What does your Kubernetes cluster cost today, and what would it cost on [UpCloud](https://upcloud.com)?**
Install one Helm chart. It reads what runs in the cluster and how much CPU and memory your workloads actually use,
then shows a side-by-side monthly cost report with concrete ways to pay less.

- **Read-only.** It only lists nodes, pods, services and volumes, and reads metrics-server. No secrets, no writes.
- **Nothing leaves the cluster.** Prices are built into the image; no cloud credentials, no phone-home.
- **Real usage, not guesses.** CPU at the 95th percentile and memory at its peak, per workload, collected while it runs.
- **Open source**, Apache-2.0.

## Quick start

Needs [metrics-server](https://github.com/kubernetes-sigs/metrics-server) (`kubectl top pods` works).

```sh
helm install cost oci://ghcr.io/moveinfra/charts/cloud-exit-cost-analyzer -n cost-analyzer --create-namespace
kubectl -n cost-analyzer port-forward svc/cost-cloud-exit-cost-analyzer 8080
open http://localhost:8080
```

Or from the Helm repository:

```sh
helm repo add moveinfra https://moveinfra.github.io/cloud-exit-cost-analyzer
helm install cost moveinfra/cloud-exit-cost-analyzer -n cost-analyzer --create-namespace
```

The first report is ready after a minute. Leave it running for **a week** so the usage numbers cover weekly peaks;
history is kept on a 1 Gi volume across restarts. Download the report as HTML or JSON from the page.

Remove it with `helm uninstall cost -n cost-analyzer` (the history volume is kept; delete the PVC to remove it).

## What the report shows

| Section | How it is calculated |
|---|---|
| **Today** | Node instance types × on-demand list price (AWS, Azure built in), managed control plane, persistent volumes by type, load balancers. Everything it cannot price is listed under “Not included”, so the number is a lower bound. |
| **UpCloud: Same servers** | Every node replaced by the cheapest UpCloud plan with at least the same vCPU and memory. |
| **UpCloud: Current requests** | Your pods' current requests packed onto the cheapest set of equal UpCloud servers, keeping 10% of each server for the system and at least 3 nodes. DaemonSets are counted on every node. |
| **UpCloud: Right-sized** | Same, with requests lowered to measured usage (+25% CPU, +15% memory headroom), one shared load balancer and unused volumes removed. |
| **Ways to pay less** | Over-requested workloads with suggested requests, under-requested memory (eviction risk), workloads without requests, unused volumes, extra load balancers. These save money on any cloud. |

All targets include UpCloud Managed Kubernetes, MaxIOPS block storage and Managed Load Balancers.
Current-cloud prices are converted to EUR with the ECB reference rate. Prices exclude VAT and your discounts.

## Configuration

| Value | Default | Meaning |
|---|---|---|
| `upcloud.zone` | `de-fra1` | UpCloud zone to price |
| `estimate.minNodes` | `3` | Never plan fewer worker nodes |
| `estimate.cpuHeadroom` | `0.25` | Right-sized CPU = p95 usage + 25% |
| `estimate.memoryHeadroom` | `0.15` | Right-sized memory = peak usage + 15% |
| `estimate.nodeReserve` | `0.1` | Share of each server kept for OS and kubelet |
| `current.discount` | `0` | Your discount on compute list prices (0.2 = 20%) |
| `current.priceSpotAsOnDemand` | `false` | Count spot nodes at on-demand prices |
| `current.instancePrices` | `{}` | Price per hour by instance type, for GCP, DigitalOcean or negotiated prices |
| `sampleInterval` | `60s` | How often usage is sampled |
| `persistence.enabled` | `true` | Keep usage history on a PVC |

GKE or DigitalOcean: built-in prices are not there yet, so set `current.instancePrices` for your node types:

```yaml
current:
  instancePrices:
    e2-standard-4: 0.155
```

## Prices

`internal/pricing/data/` holds the price lists, generated by `tools/pricegen` from the providers' own APIs:
the [AWS Price List](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/using-ppslong.html) bulk files,
the [Azure Retail Prices API](https://learn.microsoft.com/en-us/rest/api/cost-management/retail-prices/azure-retail-prices),
the [UpCloud API](https://developers.upcloud.com/1.3/4-pricing/) and the [ECB](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html) euro rates.
A monthly workflow refreshes them and opens a pull request.

## Limitations

- Data transfer (egress), backups, NAT gateways and anything outside Kubernetes are not visible from inside the cluster.
- Spot and serverless (Fargate, virtual) nodes are not priced by default.
- Usage comes from metrics-server snapshots, so very short spikes between samples are missed.

## Development

```sh
go test ./...
go run ./cmd/analyzer        # uses your current kubeconfig context, read-only; open http://localhost:8080
helm lint charts/cloud-exit-cost-analyzer
```

Releases: push a tag `vX.Y.Z`. The release workflow builds the image (amd64, arm64), pushes the chart to
`oci://ghcr.io/moveinfra/charts` and updates the Helm repository on GitHub Pages.
